# CCPun Content Migration Contract — WordPress/Docs to Sanity

Status: Local UAT material. No content is published by this contract.

## Source classes

### A. Never-published draft

Examples: WordPress Draft that has never been public, Google Docs draft, local draft.

- May move directly to Sanity as Draft.
- No redirect is required because no public canonical URL has existed.
- Must not enter `/sitemaps/blog.xml`.
- Preview must be `noindex,nofollow`.

### B. Scheduled but never live

- Treat as never-published draft if the public URL has never returned indexable content.
- Preserve intended slug when useful, but no redirect is required solely because it was scheduled.

### C. Previously published then returned to Draft/Private

- Must be checked against live history/GSC before migration.
- If the old URL has search signals or backlinks, create a 1:1 permanent redirect when the replacement URL changes.
- If the same canonical URL is retained, no migration redirect is needed.

### D. Currently published on `blog.ccpun.com`

- Do not bulk-migrate during Website 4.0 hosting cutover.
- Keep the live WordPress URL until a dedicated content-cluster migration is approved.
- On migration, map old URL → new `ccpun.com/blog/.../` URL 1:1 with a permanent redirect.
- Update canonical, internal links, sitemap and structured data in the same migration release.
- Keep `blog.ccpun.com` available as the legacy redirect host after content migration so old shares, backlinks, bookmarks and citations continue to resolve.

## Normalized fields

Every imported article should map into the Website 4.0 provider contract:

- id
- title
- slug
- excerpt
- category
- tags when useful
- author
- native Sanity Draft/Published state
- editorial review status
- featured image + alt + optional caption/credit
- body
- visible FAQ items when the article genuinely contains Q&A
- structured sources/references + publisher/accessed date when available
- SEO title
- SEO description
- canonical (generated from final route unless explicitly approved)
- GEO summary/entities/questions when useful
- publishedAt (published only)
- updatedAt (derive from Sanity `_updatedAt`)
- content/fact/compliance review timestamps when applicable

## Structured-data contract

- Draft/Review content must not emit public `BlogPosting`, `BreadcrumbList` or `FAQPage` structured data.
- Published content may emit `BlogPosting` and `BreadcrumbList`.
- `FAQPage` may be emitted only when the same questions and answers are visible in the article UI.
- Structured data must use the final canonical URL and the CCPun author/publisher entity IDs.
- Schema is generated by the Next.js presentation layer, not stored as pasted JSON-LD inside CMS body content.

## Publication gate

A content import is not publication. Imported items remain Draft until all required gates are complete:

1. Content review completed.
2. Fact/source review completed for claims that require evidence.
3. Compliance review completed when the topic/product requires it.
4. SEO title, description and canonical verified.
5. Responsive preview checked.
6. Visible FAQ and structured-data parity checked when FAQ exists.
7. Sources/references checked where required.
8. Featured image/alt text checked when an image is used.
9. Internal links and final URL ownership checked.
10. COO explicitly approves publication.

Only after publication may the production provider return the article to `/sitemaps/blog.xml` and other public article lists.

## Published WordPress migration gate

For an already-published `blog.ccpun.com` article, capture before changing URL ownership:

- current canonical URL and HTTP status
- GSC page/query performance and index state
- title/meta/H1
- schema currently emitted
- internal links and important backlinks where available
- featured image/media URLs
- existing category/slug
- meaningful published/updated dates

Then create the Sanity/Vercel replacement in Preview, verify parity, and release the 1:1 redirect + new canonical + sitemap/internal-link ownership together. Avoid redirect chains; old URL should resolve directly to the final canonical destination.
